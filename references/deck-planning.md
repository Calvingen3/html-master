# Deck Planning

The deck plan is the guardrail between raw content and final HTML. Create it before writing the full deck.

## Required Plan Shape

```text
Mode: PPT redesign | template mode | Guizang route
Audience:
Use occasion:
Visual system:

Verification:

| # | Role | Content density | Layout strategy | Asset slot | Notes |
|---|------|-----------------|-----------------|------------|-------|
| 1 | Cover | low | hero/title | none | opening promise |
```

## Role Vocabulary

Use concrete roles instead of vague page names:

- cover
- agenda
- section divider
- problem
- evidence
- quote
- timeline
- comparison
- process
- case study
- data hero
- recommendation
- closing

## Content Density Rules

- **Low density:** hero, quote, section divider, closing. Use large type and strong whitespace.
- **Medium density:** problem, recommendation, case study, comparison. Use two-column or card layout.
- **High density:** data, timeline, process, evidence wall. Split the slide before shrinking text below readable size.

If one slide needs more than 3 major ideas, split it.

## Layout Mapping

| Content shape | Preferred layout |
|---------------|------------------|
| one big idea | hero or statement |
| key metric | data hero |
| before/after | comparison |
| sequence | timeline or process |
| evidence screenshots | image grid or evidence wall |
| narrative plus image | left text / right image |
| dense explanation | section + 2-3 supporting cards |

## Theme Rhythm

Plan rhythm before coding. Avoid long runs of identical slide structure.

- Insert a visual reset every 3-5 slides.
- Avoid more than 3 consecutive text-heavy slides.
- Do not use hero scale inside compact cards or dense panels.
- Keep one visual system per deck.
- If using Guizang route, follow `guizang-ppt-skill` theme and layout rhythm instead of inventing a new one.

## Split Or Merge Decisions

Split when:

- content needs small type to fit
- a screenshot becomes unreadable
- a page combines setup, evidence, and recommendation
- animations would be needed just to hide overcrowding

Merge when:

- two slides repeat the same claim
- one slide is only a label with no narrative function
- the deck has too many weak transition pages
